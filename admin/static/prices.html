How rules are picked

A model prefix can own several rule rows, each gated by a token-count rule:

  • Over N matches when the request's prompt size is greater than N.
  • Under N (inclusive) matches when the request's prompt size is less than or equal to N.

When more than one rule on a prefix matches, the one whose token threshold is numerically closest to the request's prompt size wins — the same "most specific match wins" idea used for prefix matching itself. An exact distance tie (only possible with a literal duplicate rule) is broken by whichever rule was created most recently.
